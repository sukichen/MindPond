# 分层 Memory 能力复核（2026-10-22）

本次复核针对身份分层后，内部库、公开 Memory MCP、本机 OpenCode 适配器和人类工作台之间出现的能力遗漏。此前图接口已补齐，但已有内核测试没有覆盖实际公开入口，不能据此判断 agent 已能使用完整记忆流程。

## 已确认并修复的问题

| 问题 | 修复与验证 |
| --- | --- |
| 公开搜索丢失备用查询、深度、锚点开关、来源情境及模型参数 | HTTP 与 OpenCode 共用检索 schema；验证真实 MCP 参数和模型选择错误 |
| 使用报告宣告 `success`，内核实际接受 `completed` | 共用 `completed/partial/failed/unknown` 契约，恢复纠错线索、来源和共同使用报告；真实调用验证报告及建议生成 |
| 保存预检、历史/撤销、画像、导出、里程碑批处理、整理与恢复没有公开路径 | 同一身份边界下增加按需发现的高级操作；覆盖预检无写入、版本冲突、独立回执、幂等重试和部分完成 |
| 不同归属对同一 URI/情境的来源观察互相影响 | 按实际记忆归属存储观察，要求引用已记录于可读记忆；验证来源新鲜度隔离 |
| 工作台新建表单依赖隐藏的域/空间字段 | 新建只选择归属和知识维度，实际 HTTP 验证物理归属及分类 |
| 工作台整理默认落在人类范围，筛选自行拼装命名空间 | 整理页明确选择人类/角色/办公室；服务端读取存储映射；验证搜索、列表、整理请求、停用角色的保留知识 |
| 切换整理归属时较慢的请求覆盖当前页面 | 列表与详情使用请求版本和归属检查，过期响应不应用到新视图 |
| 办公室更名时返回猜测的命名空间 | 更名只更新显示标题，始终保留已存储的归属映射 |
| 首次连接文档仍导出域选择时代的提示 | 改为导出公开分层 MCP 的实际初始化提示，宿主生命周期文档明确标为管理集成 |
| 评测入口未同步新工具，可能通过高级操作绕过只读组 | 评测同时限制直接工具和内层操作，检索组不允许保存/整理；实现指纹包含新增模块 |

图工具的上一轮修复继续保留：关联权重、依据复核、锚点、多跳分数、六邻居上限，以及锁定办公室记忆的关联和满额替换保护。检索分数用于本次查询排序，关联权重描述有情境依据的共同回忆强度，均不代表事实正确率。

## agent 如何发现能力

1. 用 `memory_identity` 核对当前聊天身份；`memory_brief` 获取任务相关知识。
2. 首次需要高级操作时调用 `memory_capabilities`，读取实际目录。
3. `memory_action({"tool":"memory_edit_history","describe":true})` 取得该操作的准确 schema。
4. `memory_action({"tool":"memory_edit_history","arguments":{"nodeId":"实际读过的记忆 ID"}})` 执行。

HTTP/stdio 与本机 OpenCode 使用同一操作注册表和权限检查。高级 schema 按需读取，不把完整目录反复塞入每次工具描述。`memory_finish` 为每个保存、编辑、使用报告保留独立回执，失败项不抹掉成功项；再次提交相同 stage/item 内容可恢复，改变已提交内容会冲突。收到回执后检查每一项结果。

整理从实际读过的 membership ID 开始，范围由服务器推导。任务/请求编号只用于定位，不授予权限；角色离开办公室后，不能通过历史请求、来源查询或批处理重试继续访问。更新、撤销、整理提交及关联替换在实际写入时重查授权。锁定规范仍由人类编辑；来源观察只记录核对证据，不改写规范正文。

## 哪些能力仍属于明确的管理操作

- 模型安装、索引启用、全局维度和保留策略由人类管理。
- 原始聊天采集、自动抽取、宿主生命周期队列需要明确配置与授权，不随 Memory 接入自动安装。
- 全局破坏式去重替换为有范围的候选查找和保留来源的整合；固定 L2/L3 聚合使用有依据的画像综合流程。
- 角色/办公室身份不能从模型参数选择。语义空间用于分类与放置，默认检索跨空间；它不是 workspace 身份或租户选择器。

这些边界在代码契约中逐项记录，不能用“保留内部实现”代替公开能力验收，也不为所有历史工具名添加兼容别名。

## 持续检查

`src/core/memory-capability-contract.ts` 对实际库级 Memory 工具逐项指定公开路径、替代流程或管理边界。测试读取真实工具目录做对比；新增/删除能力而未作出明确决策时，检查失败。

| 命令 | 实际覆盖 |
| --- | --- |
| `npm run verify:memory-capabilities` | 认证 HTTP MCP 发现、schema、检索、使用反馈、来源隔离、历史/撤销、导出、批处理、整理恢复、跨角色及办公室撤权 |
| `npm run verify:layered-memory-graph` | 图关联、分数、证据、度数、锁定拓扑及写入期间撤权 |
| `npm run verify:opencode-native` | 实际 Node worker、多聊天、身份与图操作、重连和撤权 |
| `npm run verify:owner-workbench` | 编译后实际 Web 服务、存储映射、归属筛选、锁定/来源展示数据、新建分类、整理及管理权限 |
| `npm run verify:memory-ui` | 前端事件、表单与筛选请求、延迟响应及页面结构回归 |
| `npm run check` | 上述检查及现有数据库、身份、协作、发布包、许可证等回归 |

均使用隔离的合成数据库；本轮不运行外部模型、不触碰生产实例。接口回归证明列出的契约，不能证明真实模型会自然选择正确操作，也不能证明记忆质量、生产负载和离线目标机器已验收。真实 agent 的质量对照仍按[评估手册](quality-evaluation.md)执行。

升级不新增依赖或数据库结构迁移，不自动改写已有记忆。更新全部实际运行的 Web、HTTP/stdio MCP 和 Node worker 后重新连接；页面资源已更新版本。完整迁移与备份要求见[升级历史](history.md)。
