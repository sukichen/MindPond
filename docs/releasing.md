# 验证与发布

此仓库只分发程序、通用文档和人工编写的合成 fixtures。私人使用记录、线上基线、数据库、截图中的个人内容和模型权重不属于公开测试材料。

```sh
npm ci
npm run check
npm run verify:standalone-package
npm run verify:client-bundles
npm pack --dry-run --json
```

核心 `check` 使用隔离数据库、确定性向量及协议回归。`verify:standalone-package` 创建真实 tarball，在干净消费目录安装并验证 SDK、HTTP、MCP 和依赖。客户端契约测试需要对应 CLI；真实模型自主使用和语义整理仍需单独评估。GitHub CI 使用可公开安装的 CLI 检查配置，不使用个人账号或生产库。

## 协作功能回归用例

`npm run verify:office-resources` 执行真实 HTTP MCP/管理接口和隔离 SQLite 测试，以及加载实际前端模块的异步交互测试。所有人物、源码、消息和记忆均为合成数据；向量生成使用确定性替身，不调用模型服务。

| 场景 | 必须保持的结果 |
| --- | --- |
| 跨角色、跨办公室读取源码；伪造归属；宿主撤权或成员调离 | 拒绝越权，角色私有脚本随角色迁移，共享库随办公室权限变化 |
| Unicode 分页下载、中途修改、损坏响应 | 固定版本，完整拼接后校验 SHA-256；拒绝混版或损坏下载 |
| 并发编辑、锁定、删除后重试和编号复用 | CAS 只有一方成功；人类锁不可绕过；删除后不复活、不发生陈旧操作误删 |
| 收到邀请、加入/离开、同时多个讨论、65 条邀请后加入 | 未加入不能读发言；每角色仅一个焦点；普通消息留待处理；邀请上限不遮住焦点 |
| 等待时有新发言 | 请求真实保持等待并被消息唤醒，使用讨论专属游标 |
| 保存结论响应丢失、相同请求并发、256 字符操作键 | 重试返回同一份独立记忆；修改载荷复用键报冲突 |
| 生成向量期间关闭讨论 | 拒绝保存，不留下记忆和部分回执；关闭删除临时正文，独立记忆保留 |
| 实时更新、保存失败后讨论版本变化、切换页面/退出登录 | 展开状态和草稿保留；重试使用原版本/操作键；迟到响应不泄露内容或触发下载 |
| 断开、切换到已识别聊天、选择已占用聊天 | 检查版本、撤销凭据；保留角色知识/源码；不覆盖其他角色 |
| 重启、到期、永久删除角色/办公室 | 持久化资料可恢复；按范围清理临时资料；SQLite 完整性及外键检查通过 |

原有功能继续由 `npm run check` 中的角色连接、分层记忆、关联边上限、消息闭环、等待取消、UI 异步刷新、场景碰撞、回放、迁移、离线依赖、许可和发布扫描覆盖。资源 UI 测试采用 DOM 替身验证真实事件处理代码，不等于浏览器布局验收；实际 Codex/OpenCode 宿主和模型自主行为仍需分别验证。

`npm run verify:office-meetings` 已纳入默认 `check`，执行实际会议室控制器：验证八座满员进出、封门拒绝穿墙、多会议室切换、双人相对座位、逐人通道占用、离开/关闭返座、实时重绘与成员变化同时发生、隐藏面板/列表视图、减少动效、回放隔离和定时器清理。管理快照用例另验证文档版本未变时仍携带会议室变更、过期房间不入场景，以及场景元数据不包含临时问题和发言正文。浏览器实测需再确认实际走动、朝向、缩放聚焦和桌椅显示。

进一步的异常转换用例覆盖：首个人物无路可走时其他人物仍可通行、腾位后重新规划、动画异常取消后的有限重试、跨房间途中重绘并关闭源房间、通道中等待保持站立、隐藏实时家具不影响历史回放、会议室刷新保留普通消息交接的行走标记，以及重置清理回放归属。新增用例先复现相关失败，再运行默认回归。

源码目录中还可使用已安装客户端执行隔离的真实宿主验证：`MINDPOND_TEST_CODEX_BIN="$(command -v codex)" npm run verify:codex-role-session`、`MINDPOND_TEST_OPENCODE_BIN="$(command -v opencode)" npm run verify:opencode-role-session`。它们使用临时配置和合成数据库，验证原生聊天身份与角色记忆，不发起模型推理；不属于不依赖客户端的默认 `check`。

## 发布边界

`verify:release` 扫描拟发布源码、编译结果和 npm 清单，拒绝常见私人文件、硬编码凭据、本机路径、私人评估目录和未列入白名单的材料。测试伪密钥只按少量明确路径和值放行。检查不是通用秘密识别器；每次发布仍应审查 diff、文件清单、fixtures 的内容和截图。不要对原始用户资料只替换姓名后声称匿名。

新增公共文档时更新 package.json 的明确文件列表，并审查其数据来源。`npm run verify:licenses` 核对锁文件和第三方许可清单；依赖变化后运行 `node scripts/generate-license-notices.mjs` 更新声明，并人工核查新许可及实际捆绑代码。

真实模型评估只接入明确的宿主适配器，凭证留在宿主；运行材料与回复保存到仓库外。使用相同任务、代码快照、模型与上下文预算比较直接检索、涟漪、锚点和整理，同时保留失败与无须记忆的任务。评价事实和条件保留、误用、实际采用、维护成本及最终任务结果，不能只看记忆条数或合法 JSON。

项目使用 MIT；第三方依赖与模型维持其自身许可。当前源码/npm 包不捆绑原生依赖和模型权重。若发布 Docker、离线依赖包或单文件可执行程序，须额外核查所含二进制、codec、模型的通知、源码和用户修改/替换条件。
