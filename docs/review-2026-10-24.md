### 本次发现与处理

1. **角色目录的宿主状态不更新**：只有宿主改名/停用、没有角色事件时，`role_events` 和目录条数都不变，增量接口错误返回 unchanged。新增用例先复现失败，再把宿主配置/删除的已有索引审计版本纳入目录版本，不增加表或计时器。
2. **异步配置切换能抹掉失效标记**：切换身份请求期间后台策略改变，旧表单被标记只读，但请求返回会重建可签发表单。新增真实页面回调用例先复现失败；现在开始切换就保留操作草稿，返回时重新核对失效标记，保留草稿并要求重新读取。
3. **分页后的引用遗漏**：角色未加载详细卡片时，办公室表单的空工位称呼不能采用角色名。新增真实提交回调用例先复现空字符串；表单、事件称呼、项目成员名称和账户推断现在使用完整精简引用，卡片列表继续分页。
4. **凭据确认的登录边界补强**：在打开确认框前固定登录代次；确认期间退出/重新登录或表单已移除时，不再签发凭据。新增延迟确认回归。

删除切换目标必然存在回退对象后的无效判断、表单中的重复角色变量，以及测试调用里不被配置包 API 接受的多余参数。未拆出重复权限入口，未删除角色迁移、办公室锁定或断开取消等有效防护。

## 办公室、会议室与角色切换专项复核

### 七处已复现并修复的问题

- **凭据限制误改会议成员**：角色仍属于办公室 B、正在 B 会议中，用只允许 A 的凭据同步会把 B 成员状态改成 left。现在只收窄当前视图，返回 `activeUnavailable`，不泄露 B 的标题/发言，也不擅自退会或允许普通取信；实际办公室成员资格失效时才释放焦点并更新讨论版本。
- **关闭会议清空全局分页**：原清理会删除全部 `office_response_pages`，导致无关协作的完整响应无法续读。讨论正文原本就不进该缓存，已删除这处全局清理。权限变化时既有必要失效继续保留，分页反馈明确这是调用快照、需要核对当前状态。
- **办公室新消息未核对收件人成员资格**：带 `officeId` 的点对点消息可以送给办公室外的角色。现在与广播一样，在写入事务中核对成员；失败不投递，也不自动改成直接消息。账户通信授权继续检查。
- **等待把无权查看误报为已结束**：未受邀角色等一间仍存在的会议会收到 closed=true。现在保留 not_found；只有确认临时房间确已删除时返回 terminal/closed，并提醒核对 role_sync、恢复邮箱，而非宣告任务完成。
- **领取重试给 LLM 的提示过时**：已完成的消息重放领取回执时状态虽为 archived，指引仍要求处理，result 还是领取时的空值。现在根据当前状态给出处理/已归档/本次未领取的指引；归档回执不冒充最新反馈正文，可用 office_message get 读取实际结果。稳定操作键、完成反馈去重和无回执循环不变。完成响应另用 `feedbackDelivery` 明确区分 queued、not_required 和 sender_unavailable，避免把处理完成误认为已通知或已读。

- **不可访问的邀请挤占预览窗口**：先 LIMIT 再过滤权限时，70 条其他办公室邀请会把后来的可访问邀请完全挡住。回归夹具同时验证原始未过滤窗口确实遗漏该邀请，再验证实际接口返回该邀请；改为在 SQL 分页之前过滤可访问邀请，同时单独保留当前焦点以便安全提示。

- **讨论参数的办公室范围被忽略**：同时传入讨论 ID 和不相符的 officeId 时，读取仍返回另一个办公室的讨论；同一分支也用于关闭。现统一核对源办公室，读取、等待和关闭均拒绝不匹配范围，等待续传保留该范围。

### 联合验收

4. 真实办公室移除后，共享记忆、任务、讨论和新发送立即拒绝；角色私人知识、明确投递给自己的通信历史保留。

## 会议增员、观测与总结退会（本轮新增）

本轮按用户要求补齐协作闭环，并复核新状态、通知和错误语义：

- 已加入角色的普通发送、引用回复、广播和交接被统一拦截；向会外角色完成消息也会被拦截，原消息保持处理中。同会已加入成员之间的原有完成反馈保留。错误说明所在讨论、原因和正确操作，不把权限问题伪装成任务完成。
- 增员申请由角色发起，只有用户能批准或拒绝；版本比较与相同请求去重。批准仅产生邀请，不强制加入，也不增加办公室或记忆权限。申请人可撤销自己的申请，完整原因与审批意见按需读取；卡片保留全部待审批和有限最近记录，避免把长介绍、申请正文塞进每次响应。
- 实际返回的讨论发言才记为服务已提供，人类查看不改变角色记录，跳游标不确认遗漏内容；角色读取响应中的待取数同时更新，避免给自身显示过时状态。界面明确不证明传输、模型理解、完成或宿主在线。等待观测核对绑定代次、宿主状态与最近三秒记录，断开、换绑、取消、超时后释放；成员卡片不使用浏览器时钟判断服务端是否在等待，也将 SQLite 的绑定布尔值转换为真正布尔值。
- 自愿退会需 `summary/key`，同一事务先写总结再退出，事务提交后发送明确选择的通知；失败不是回滚已经完成的退会，而是保存角色自己拥有的待发草稿及错误。`role_sync/departures` 支持换聊天、重启恢复；查询私有草稿不允许冒用其他角色。
- 通知每次入箱与草稿回执同一事务，丢包重试、并发重试、换聊天重试不重复入箱；重放上一次退会不会退出新一次会议。默认办公室通知不暗中降级成直接通信，只有显式 `officeId:null` 才走直接通信授权。
- 草稿仅保留待发正文。发送成功后保留普通消息编号，取消后删去未发正文；不额外永久复制完整临时讨论。普通发言满额仍可写有独立上限的退会总结；预留总结键禁止普通发言使用，避免绕过配额。紧急人类关闭、到期、撤权不要求模型必须先运行总结。
- 所有业务错误码都有原因与纠正入口，HTTP 快速认证/初始化/容量失败与关停反馈也保留结构。未知内部/存储错误不回显内部路径；故障审计写入失败不会覆盖原业务拒绝。底层协议输入校验继续提供具体字段。
