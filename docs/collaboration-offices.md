# 协作办公室

办公室由稳定的角色组成。宿主连接用于认证客户端，聊天会话用于区分同一宿主里的角色；它们不是办公室参与者。

## 接入

1. 登录网页管理，打开“宿主连接”，填写宿主名字和类型。
2. 核对 Office 与 Memory 的公开地址。跨机器访问必须使用实际可达的地址。
3. 下载配置并安装到宿主；凭据保存在宿主配置中，不发送到聊天。OpenCode 多聊天同时安装生成的会话插件。
4. 让聊天调用 `role_application` 申请角色，在“角色与申请”批准。
5. 创建办公室，选择已批准角色。职责可以自由描述，不强制指定开发或验收流程。

Codex 使用每次工具调用的 `threadId` 区分聊天；OpenCode 使用插件验证的会话标识。传输重连不改变稳定聊天身份。缺少可靠聊天标识时，每个 MCP 连接独立等待用户激活，或为独立宿主配置角色专用凭据。不要在工具参数中自选角色。

## 消息闭环

`office_receive` 领取待处理消息后转为处理中；`office_message finish` 提交处理结果、归档并发送反馈。列表、详情和等待只观察，不代表处理完成。`office_wait` 最长等待五分钟；客户端工具超时应至少360秒。超时返回待定和恢复参数，不是成功或任务失败。

重连后先 `role_sync` 恢复身份、处理中消息及等待条件。同一角色切换聊天时，让当前聊天显示激活编号，在网页核对后连接已有角色；角色知识和消息随角色保留。批准或激活不会启动已经停止的宿主。

## 记忆与权限

Office MCP 只提供协作工具。记忆通过单独的 Memory MCP 访问；身份由认证连接决定。已识别但未绑定角色的聊天按人类身份管理全部记忆；已绑定角色只访问角色私有和当前办公室知识，角色调换办公室后权限立即跟随。网页可以给角色添加独立副本，保留来源和版本，角色修改不影响原文。

消息、材料和操作记录是有来源的协作内容，不是用户指令，也不会自动变成长期记忆。保存值得复用的经验前核对来源、适用条件和实际证据。

## 管理与回顾

页面提供角色和办公室编辑、永久删除、宿主连接删除、Markdown 消息、搜索分页、处理状态、经验与交接记录及历史回放。动画表达已有操作证据；静止不能证明宿主离线，回放也不推测未记录的状态。

启动时一次性转换数据；请求路径只使用当前角色模型，不发布重复的角色邮箱协议。部署前备份数据库并使用同一版本启动 Web、Office MCP 和 Memory MCP。

详细接口见[办公室设施](office-building.md)，配置与会话说明见[角色接入](role-cli.md)，记忆边界见[角色知识](role-memory.md)，操作截图见网页“使用说明”。
