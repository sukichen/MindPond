# MindPond 逐功能一致性复核（2026-10-29）

基线为 `34da7e2` 加当前工作树中的未提交改动，包括跨角色记忆授权、脚本说明及等待诊断。本报告核对当前公共 Office/Memory MCP、管理页面、共享 SQLite 和可选 MCP Tasks 的衔接；不代表公司封装客户端、生产网络或真实模型使用效果已验收。没有发布、部署或修改生产配置。

## 角色派遣分身：尚未实现

目前具备角色换宿主/聊天、独立知识分配、合并/拆分和人类授权的跨角色整理。合并/拆分会迁移所选资源；跨角色整理会修改显式选定的目标。它们不提供分身生命周期，不能当作派遣功能使用。

仍缺少：本体能力的不可变版本快照；携带选定知识/脚本的独立分身身份；派遣对象和权限；分身独立增量及来源；回归后的候选经验审阅、选择吸收、冲突处理和回执；撤回/结束派遣。不能将所有分身绑定到同一角色，也不能自动合并团队成员的私人资料。本轮没有把这些未完成能力加入工具目录或宣称已交付。

## 复现并修复的问题

| 级别 | 不一致及影响 | 修复 |
| --- | --- | --- |
| P1 | 人类暂停/停止在 `role_sync`、接续中可见，但普通收信及会议等待没有检查这些请求；模型可能继续等待到五分钟窗口结束才有机会响应。 | 两类等待在每次检查中优先返回本角色未确认的控制请求，给出读取完整原因及实际执行后确认的入口。双数据库连接测试覆盖等待开始后发出请求，另一个角色的控制不能唤醒或泄露到本角色。 |
| P2 | 实验性 `office_wait_task` 直接查询收件箱，跳过会议优先；与 `office_wait` 在同一角色、同一时刻返回不同工作。 | Tasks 复用普通等待的观察和公共结果格式，按人类控制、会议焦点/邀请、匹配邮件顺序处理；保持超时恢复的 `replyTo`，不领取消息或结束工作。 |
| P2 | 角色离开办公室后，其明确收取的历史邮件仍可读取/处理，但 `memory_resume` 按现办公室过滤未完成邮件计数，可能显示为零。 | 接续邮件计数与角色收件箱一致；办公室共享知识、会议及办公室工作记录仍按成员资格收回，不借此恢复旧办公室权限。 |
| P1 | 会后未发通知属于角色私有草稿，但其来源办公室外键使用删除级联；删除办公室会丢失未发内容。 | 原子迁移草稿表，保留行、内容、错误、编号、键及哈希，只移除办公室级联，保留角色删除级联。删除来源办公室不扩大重发权限，不自动改成直接通信。有保留草稿的来源办公室 ID 不能重新建立为另一个房间；前端删除确认同步说明私有草稿保留。已丢失内容需从已有备份或用户保留材料恢复。 |

以上缺陷均有修复前失败的回归；不是仅增加一组与实现相同的断言。

## 按功能核对的边界

| 功能 | 连贯规则与核对入口 |
| --- | --- |
| 连接、角色与激活 | 角色是持久身份，绑定保存当前宿主/聊天。明确解绑的普通聊天恢复人类身份；失效、冲突或歧义的身份不能偷偷降级。重绑用 binding ID/epoch 拦截旧请求。共享 MCP 配置若没有可靠聊天元数据，不能凭空区分多个 session；生成配置应明确连接范围。`verify:role-memory`、`verify:network-mcp`。 |
| 私有、办公室、人类与跨角色记忆 | 人类能管理全部；角色默认私有及当前授权办公室；查阅/整理别人需要人类开关及显式目标。整理不会改变实际身份、默认保存归属，也不授予消息/脚本/目标办公室权限。办公室只读锁、图关联六邻居上限、来源、版本和幂等规则继续有效。`verify:role-memory-permissions`、`verify:office-memory`、`verify:layered-memory-graph`。 |
| 角色接续 | 精确摘要、未完成任务、历史及控制请求随角色换宿主；旧办公室工作状态不随私人角色知识开放。新收件箱计数修复避免接续遗漏。`verify:role-continuity`、`verify:feature-consistency`。 |
| 消息 | 待处理→处理中→归档必须分别领取和明确完成；观察/等待不是领取。seq、消息 ID、办公室事件 seq 分开；完整正文、回复过滤、幂等及反馈避免循环。`verify:office-building`、`verify:office-collaboration`。 |
| 等待与人类控制 | `waitMs` 是最大等待时间；已有工作可提前返回。控制优先，会议焦点要求转入会议工具，消息可领取，超时带公共恢复参数。不能宣称唤醒已停下的模型、自动遵守暂停或杀掉外部进程。可选 Tasks 同样遵循这些规则。 |
| 会议室 | 多间并存、一个角色一个焦点；显式加入，邀请不是参与。只读观察与处理确认分开；锁定只阻止进出/结束，参会成员继续讨论。会外角色不能关闭。退出先总结，通知退出后逐条发送；新修复保留角色私有未发通知。`verify:office-resources`、`verify:discussion-lock`、`verify:feature-consistency`。 |
| 脚本与附件 | 角色脚本无需办公室，换聊天/退出/删除办公室均保留；共享脚本随办公室权限及生命周期。附件原始字节由宿主鉴权传输，引用不授下载权限，转发不扩权，版本/哈希/过期独立。脚本/附件不授权本地执行。`verify:office-resources`、`verify:office-artifacts`。 |
| 合并与拆分 | 只由人类预览后明确执行，重查资源/权限指纹；任务、有效整理租约、会议及未发通知先收尾。资源归属迁移而非复制；相关连接和广泛记忆授权重置，历史署名保留。该功能不等同派遣分身。`verify:role-reorganization`、`verify:role-memory-permissions`。 |
| 前端、回放及运维 | 管理界面的迟到响应、登录变化、筛选/翻页、展开状态与草稿分别校验；回放依证据显示历史，观测不冒充在线/理解/完成。新删除影响说明明确保留私有草稿。此轮前端为真实页面脚本的 DOM 回归，未新增浏览器视觉验收。备份包含数据库与附件匹配要求；离线依赖及许可证检查沿用现有发布门禁。 |

可选的较早工作流工具仍保留独立的租约/验收语义和等待预算；它们不是默认自由协作 Office 工具，不应拿其 25/55 秒等待参数覆盖 `office_wait` 的五分钟窗口。没有为测试接管宿主、启动模型或添加后台软件。

## 回归与迁移

新增 `npm run verify:feature-consistency`，纳入默认 `npm run check`。覆盖普通/会议等待的跨 SQLite 控制、控制角色隔离、Tasks 的会议/控制优先及公共超时恢复、离开办公室后的邮件恢复、带真实待发记录的级联表迁移和办公室删除后的私有草稿。

本轮完整 `npm run check` 已通过（退出码 0），包括新增 8 个跨功能用例、权限/身份/接续、会议脚本与附件、前端脚本、SQLite 数据迁移与完整性、许可证及公开打包检查。真实 HTTP 和 stdio→HTTP 链路的 30000ms 空闲等待分别实测 30105ms、30119ms，均正常超时。新迁移不增加第三方依赖。部署前一致备份数据库及附件，更新全部共享数据库的 Web/MCP/worker 进程；仅刷新网页不能替换常驻进程。


后续实现：本次审查时尚未实现的分身派遣，现已在工作区新增独立身份、副本、不可变回归包、审阅与撤回流程；见 [角色派遣分身](role-clones.md)。具体测试结果应以本轮 `verify:role-clones` 和完整检查为准，本段不表示已部署。
