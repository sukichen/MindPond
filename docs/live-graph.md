# 实时空间图谱

启动 MindPond HTTP 服务后打开 `/graph`，或从工作台的「空间图谱」进入。页面是独立的大画布。点击节点可查看完整正文；agent 调用 HTTP/MCP `memory_search` 时，每条实际进入召回响应的记忆都会产生 `memory_read` 事件。`memory_expand` 和显式计数的直接读取也会产生读取事件。前端只沿召回结果给出的真实路径播放涟漪，不把未返回的邻居误标为已读取；在对应节点旁显示正文摘要、召回深度和得分，详情栏显示完整正文；读取节点不在当前图谱窗口时会临时加入视野。卡片随平移、缩放移动，并在九秒后收起；动作流保留最近的记录。

页面从受管理权限保护的 `/api/memory/actionstream` 接收可续传的 SSE 动作流；连接中断时用 action log 轮询兜底。接口遵守服务 API key 和 operator capability。读取日志只存节点 ID、召回 ID、深度和分数，不复制记忆正文；前端凭管理权限读取节点当前正文。若记忆在读取后被修改，页面显示的是最新正文，不宣称它是不可变的历史快照。仅渲染 action log 中有记录的后端操作，未进入日志的内部计算不会伪装为已发生动作。

默认尝试高性能 WebGL2，并检测软件渲染器或着色器失败后自动切换 Canvas 2D。两种模式使用同一布局、节点和事件数据；用户也可手动切换。GPU 选择由浏览器和操作系统决定，`powerPreference: high-performance` 只是提示。无需 NVIDIA 专用代码或驱动依赖；缺少可用独显驱动的机器会使用集显或 Canvas。布局只在加载时进行有限次数的整理，播放动作动画时不会重新跑力导向计算。静态页面无外部字体或 CDN 依赖。

图谱用记忆维度给节点着色，并按当前数量分配画布区域；同一记忆属于多个维度时，节点核心与外圈分段显示各维度颜色，并放在这些维度之间。关联边以弧线呈现，点选记忆后突出其真实关联；维度说明和筛选放在画布边缘，不在空间里摆放固定的类型标签。节点大小按可用画布面积和数量收敛，窄屏也保留可辨认的单点。

点击记忆时，图谱沿真实关联边向外传播，优先显示相关性乘积最高的路径。每经过一条边都会乘以该边权与跳数衰减系数；同一节点可由多条路径到达时取最强路径。可见传播在相关性低于阈值时停止；另有深度与节点数保护上限，避免异常稠密的图谱拖慢页面。此探索动画不代表 agent 已读取所有被点亮的记忆；实际读取仍以 `memory_read` 日志和召回路径为准。

默认图谱即使只取最近 500/1000 条，也会为当前空间中实际存在的各知识维度保留至少一个代表节点；过滤特定空间或类型时不会从别处借节点。图例按 `dimensions` 的完整身份计数，多维记忆会在多个维度出现，因此各项之和可能大于节点总数。图例随数据库中的自定义维度配置更新；某维度在当前筛选中为空时显示 0。只筛出一条记忆时会放大节点、附着显示短标题，并在详情栏展示正文。
