# 通用 MCP 接入与生产验收

## 先选择身份范围

所有普通连接模板默认使用通用连接身份，不按宿主名字推定其能力。无需插件、启动脚本或聊天元数据；共享一份配置的聊天共享角色，需要独立角色时分别登记、配置独立连接。已验证宿主确实提供可靠聊天标识时，可手动选择逐聊天增强。导出设置不改变已有绑定；正在使用逐聊天模式的连接重新导出时仍需选择逐聊天模式。

在“宿主连接”展开配置，选择识别方式，再“生成并下载完整配置”。下载文件同时包含独立的 Office 和 Memory MCP 入口及访问凭据；私下合并到宿主设置，不提交仓库、不发给模型。无需启动脚本；高级环境变量模板仍可使用。只替换这一组 MindPond 配置，保留宿主的其他配置。

| 方式 | 适合什么情况 | 实际范围 |
| --- | --- | --- |
| 通用连接身份 | 标准 MCP 客户端，无插件、无聊天元数据 | 共享一份连接凭据的聊天共享一个角色；需要不同角色时创建独立连接并分别配置 |
| 逐聊天身份 | 宿主能提供真实聊天标识 | 同一宿主不同聊天可绑定不同角色。支持该能力的 Codex 提供 threadId；OpenCode 可选会话插件。缺标识时 Memory 明确拒绝，不猜测 |

通用模式在配置中添加 `X-MindPond-Identity: connection`，两个入口使用同一凭据，服务器从认证凭据推导稳定身份。重连、transport 老化不会生成新角色；该头不能在工具参数中指定。已批准角色只能访问自己的记忆及当前办公室知识；明确未绑定的连接/聊天按单人实例的人类身份访问所有知识。共享凭据不是不可信用户间的隔离边界。凭据轮换后同一连接身份保留，撤权立即阻止后续调用。

没有可信聊天标识的宿主无法仅靠服务端区分复用的聊天。不能把通用模式说成逐聊天隔离，也不能把未知身份当成人类。若想从逐聊天切换到通用模式，先核对并断开原角色绑定，在新连接身份上激活同一角色；知识与办公室关系保留，不自动搬迁、覆盖已有绑定。查看 `role_sync` 和 `memory_identity` 核对结果。

若凭据限制了可用工位，已绑定角色的办公室记忆和接续范围必须与 Office 使用相同的权限交集；不能仅按角色的全部办公室成员关系放行。生产副本验收应包含一个角色属于两个办公室、凭据只允许其中一个工位的场景。

### 客户端只支持 stdio

在宿主机器准备 MindPond 程序后，使用现有 `mindpond-mcp-remote` 桥接。它提供标准 stdio，不要求修改客户端。配置两个进程，同一凭据、同一 `--identity connection`；Office 的 URL 为 `/mcp`，Memory 为 `/memory/mcp`：

```sh
mindpond-mcp-remote --url https://pond.example/mcp \
  --identity connection --token-env MINDPOND_TOKEN
mindpond-mcp-remote --url https://pond.example/memory/mcp \
  --identity connection --token-env MINDPOND_TOKEN
```

上面是两条 MCP `command/args` 的写法，不是要求手动启动两个终端。由宿主把同一专用连接凭据注入两个进程的指定秘密环境变量；也可用 `--token-file /absolute/private/connection.token`，不能同时提供两种来源。凭据不放命令行参数。未全局安装时使用 `node /absolute/mindpond/dist/mcp-remote.js`。桥接转发取消，工具调用统一采用六分钟期限；宿主本身的期限仍需足够长。`--identity native` 保留逐聊天增强，需要宿主确实提供聊天标识。

## 处理中断与人工恢复

“运行状态”最多列出最早领取的50条处理中消息；更多消息可在办公室通信或角色详情查看，也可在那里打开“中止 / 重新安排”。时间长只供判断，不自动认定失败。

1. 查看原消息、角色接续记录和外部成果；服务不能撤回已经执行的命令。
2. 填写恢复说明，选“仅中止处理”或“中止并重新安排”。
3. 原消息明确记录人类中止，通知发件人；重新安排生成新的待处理消息及来源。原宿主迟到的完成请求不能完成新消息。
4. 响应丢失时保留原内容重试；修改理由或收件人前重新核对状态。已确认的取消不表示任务已完成。

没有消息领取或阶段总结也可以自由交流。接续、讨论室、脚本和经验维护均按需使用，不强制增加工作流。记忆的编辑、锁定、来源、历史、撤销仍由现有入口维护；不增加自动质量评分和破坏式淘汰。

## 离线运行目录

构建机须已安装与目标平台匹配、符合 shrinkwrap 的依赖及构建工具。下面的命令不安装包、不下载模型；缺依赖、版本不符或平台原生模块不可用时失败，并清理未完成目录。

```sh
npm run release:offline -- build --output /absolute/private/new-release
node /absolute/private/new-release/verify.mjs verify \
  --directory /absolute/private/new-release --smoke
```

生成目录包含发布包中的程序/文档/许可证、基础生产依赖、每文件 SHA-256 清单及检查器，不复制开发依赖、用户数据库、环境文件、token、模型或选装推理运行库。Node.js 不捆绑；目标须具备匹配的 OS、架构、Node major/ABI 与 libc。SQLite 是原生模块，不能假定任意机器均可使用同一目录。本地推理仍须单独按现有指南准备并验收。

将清单 SHA-256 单独记录后传输，在目标机器重新核对。校验和只能检测与记录清单的差异，不提供发布者签名认证。基础启动验收在独立合成数据库中执行文本模式 HTTP/SQLite 检查，不访问生产库，也不能证明生产模型、代理、宿主或已有数据迁移已经通过。

运行入口为 `node /absolute/private/new-release/app/dist/server.js` 与 `node .../app/dist/mcp-http.js serve ...`，配置私有数据与账户文件后再启动。不要在发布目录写入运行数据。保留上版程序、配置和一致备份；新 schema 的回退需对应备份，不能直接用旧程序打开新库。

## 发布和运行检查

正式程序版本来自 `package.json`，锁文件、MCP、Web 健康接口与管理状态统一显示。每次交付同时记录精确 Git commit、锁文件校验和与目标平台；改变接口/身份范围或迁移时更新版本及 [history](history.md)。源码仓库和正式离线运行目录是两种交付物，GitHub 源码下载不包含 node_modules。

“运行状态”展示数据库/WAL、磁盘、处理中消息、有限 HTTP 指标及最近两分钟的 MCP 进程报告。自动刷新复用最多五分钟前的完整性检查，并标明检查时间；需要最新检查时点击“检查当前数据库”。等待容量与临时记录清理集中在该页的高级项。最近通信不代表宿主或模型在线；HTTP 200 不代表工具或任务成功；进程重启后 HTTP 指标重新计数。脱敏诊断不包含正文、角色名称、消息 ID、凭据或文件路径。

“演练恢复到临时副本”会从指定备份创建、检查、删除独立 SQLite 副本，保留结果。不会切换运行数据库，也不检验外部文件与宿主凭据。创建备份、检验校验和与真正恢复演练是不同结果。

## 可重复验收

下面的 npm 命令在源码或构建环境执行，需要开发工具。离线生产运行目录不需要安装这些工具，使用前面的 `verify.mjs verify --smoke` 检查运行物料。

```sh
npm run check
npm run benchmark:production -- --memories 1000 --queries 40 --concurrency 8 \
  --output /absolute/private/new-capacity-report.json
```

容量测试仅使用临时合成文本库，记录初始化、重启、并发查询 p50/p95、内存和数据规模。需在目标硬件按实际规模复测；向量/模型、多进程竞争及真实宿主另测。真实 LLM 对照继续使用 [现有效果评测](quality-evaluation.md)，不自动启动付费推理，也不以回归通过或记忆数量宣称收益。

目标生产验收还需在备份副本上核对：同一凭据双 MCP 身份一致、独立连接互不串角色、逐聊天不同角色、缺失/冲突身份、重启与撤权、消息中断恢复、五分钟等待经过实际代理、窄窗口长文本、备份恢复和检索质量。默认回归使用合成资料，不代表目标生产实例已经验收。


### 管理目录与状态显示回归

运行 `npm run verify:admin-directory`：超过先前 128/200/500 条限制的合成目录必须能加载完整，总数不依赖已加载页；未展示连接的配置和工位授权操作仍成功；选择列表包含未加载卡片的成员。当前办公室不能因为不在目录页内而被关闭。检查接入握手、角色自报和消息领取分别呈现；通信更新不清除未保存的连接设置。目录搜索仅匹配已加载卡片，完整精简表单引用仍会传输；按实际角色数量另行做负载验收。


### 稳定轮询与凭据轮换

页面用当前内容的版本号省略未变化的精简选择目录及公开配置模板；服务仍在每次请求先鉴权并读取当前数据，不保存跨用户缓存。名称、成员、公开地址或模板改变时立即返回新内容；缺失/不匹配的页面缓存不得当成空目录。没有 SSE 的环境继续用现有轮询，不新增服务、守护进程或消息中间件。

凭据轮换保留连接编号及工位限制，自定义编号也不例外。同一宿主有多份独立凭据时，快捷重新签发不能确定身份/权限，不会任选一份并替换全部。页面明确提示分别管理私有配置，或为每份配置登记独立连接；常规单凭据连接的操作不变。

### 会议增员与总结退会

在升级副本验证 `verify:office-resources`（含 `verify-discussion-controls.ts`），并确认：

- 角色入会看见通信限制；普通发送、广播、交接和会外完成反馈拒绝且说明原因，普通消息保留。
- 前端显示真实待取发言与等待观测，申请可批准/拒绝；批准只邀请，不能绕过办公室成员及记忆权限。
- 主动退会要求总结，选定通知在退会提交后发送；部分失败有原因，重新连接同一角色可找回草稿。成功通知不重复入箱；直接通信需显式选择，不自动降低范围。
- 先备份并更新所有同库进程，宿主重连刷新工具 schema，浏览器刷新；新增四张表及清理范围见迁移历史。人类紧急关闭与到期不依赖模型先响应总结。
