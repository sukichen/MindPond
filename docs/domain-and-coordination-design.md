# Domain 与多 agent 协作设计

日期：2026-09-10。状态：`domain-memory.v1` 与 `work-coordination.v1` 已实现。能力通过 `memory_capabilities` 声明；本文同时记录产品约束和后续迭代边界。基于用户要求：session 隔离、personal 长期沉淀、team 仅由用户主动发起写入、读取便捷，以及独立的协作待办。

## 产品定位

MindPond 是跨 agent 的记忆系统，按记忆的归属和生命周期管理知识，以独立语义空间中的涟漪搜索召回关联材料。可选协作模块负责工作状态，宿主负责运行 agent、调度工作和提供 LLM。

Domain 不等于语义维度，不等于 L0/L1/L2，也不等于记忆质量。session 中可以有完整知识和临时画像；personal 中也可能有待复核的长期判断。人物、工具环境、项目、经验等不应直接变成新的 domain。

## 三类记忆

| Domain | 实例归属 | 内容和写入 | 保留与读取 |
| --- | --- | --- | --- |
| session | 一个逻辑 session | 当前目标、临时约束、调查过程、尚未确认的发现、阶段认识；允许 agent 自动捕获有价值的工作上下文 | 只供当前 session；活跃/暂停期间可持久化以恢复，结束后退出正常检索，有限宽限期后清理 |
| personal | 一个用户 | 长期工作认识、人物画像、工具环境、历史经验和有复用价值的事实；允许 agent 在明确规则下自主保存/沉淀，用户可编辑和纠正 | 跨 session、跨 agent 持续可读；定期去重、补关联、修订画像和复核来源 |
| team | 一个用户已接入的团队 | 用户主动要求共享或总结的团队知识；agent 在该请求指定的目标和范围内执行 | 团队场景可长期读取；个人模式无需创建 team。内容更新及语义整理同样需要用户发起的工作范围 |

这里“读取不受限制”指当前用户使用的 personal、已接入的 team 无需额外逐条批准，session 只读当前一个；它不隐含开放其他用户的 personal 或任意团队数据。Domain 本身不应被误当作完整账号授权系统。

Session 结束不等于一次 assistant 回复完成，也不等于子 agent 退出。宿主明确报告 active/paused/closed；进程崩溃通常是暂停。关闭后旧 session 的记录不参与新 session 检索；恢复原逻辑 session 可在清理前继续使用。用户删除/最终过期时清理节点、索引、图关系、缓存和临时证据。宽限期、存储上限及待处理沉淀的截止时间需可配置，不能因一个永远延期的 job 永久保留整段会话。

## Domain 与独立语义空间正交

建议完整范围采用结构化字段：

```text
domainRef = { kind: session | personal | team, id: domainInstanceId }
graphScope = { domainRef, spaceId, memoryType }
origin     = { hostId, agentId, sessionId, runId, messageId? }
```

`origin.sessionId` 只说明从哪个会话获得信息，不能令 personal 记忆仅在原会话可见。记忆可见性由 domainRef 决定，代码/文档版本继续由 sourceRefs 的 context/revision 表达。sessionId、runId、domainId、spaceId 和 checkout context 必须分别存储，不能靠拼接路径推导含义。

例如 personal 下可以有 project/sample-project、tooling/local、people 等空间。用户先前要求的独立维度继续通过 placements 表达：同一记忆可在多个语义空间存在，各空间独立建关联。

不要过度细分 memoryType。若项目事实、工具约束和经验本应连带召回，可放在同一知识类型，用 facets/tags 标注其类别；如果把它们拆成互不连通的类型，按现有规则它们就不会发生涟漪。只有确实需要独立关联的类型才构成图边界。

默认提案：涟漪仍只在相同 domain 实例、spaceId、memoryType 内传播，多个入口并行展开；一次搜索可并行查询多个完整范围，然后融合展示。读取多个域不要求把各域图合并。

## 统一读取与上下文预算

正常搜索上下文由宿主注入当前用户、当前 session 和已接入的 team；agent 可缩小查询范围。省略 domain 过滤表示使用该上下文的正常可读域，不表示忽略 session 隔离。没有当前 session 上下文时，普通读取排除全部 session 记忆。

检索流程：确定可读域 → 各域/空间分别选取直接命中 → 在各自图中涟漪传播 → 按相关性、证据、适用条件及版本排序 → 跨域展示去重。每个阶段，包括画像展开、候选发现、邻居查询、缓存和后台整理，都落实同一范围规则，不能只在最终列表过滤。

结果应带 domainRef、内容版本、适用条件、来源、freshness 和召回路径。同内容的个人记录和团队发布版本可以折叠展示，但必须保留两份出处和版本，不能静默当成一个可变对象。

读取自由不等于每次把所有记忆塞入上下文。按总预算提供足够的直接证据和有用关联，必要时再展开。任务看板单独提供紧凑状态视图，不占用知识搜索的全部候选预算。

不固定规定 session > personal > team 的真值优先级。session 中可能只是猜测，team 中也可能是旧约定。冲突应看适用对象、来源版本、证据和当前用户要求；未能消解就展示冲突，不拼成一个貌似确定的结论。

## Personal 的自主沉淀

session 是过程信息的默认去处，但不是所有长期记忆都必须等待会话结束才晋升。用户明确提供稳定偏好，或 agent 已确认一项可复用、证据完整的环境事实，可以直接保存 personal。

对不确定的过程发现，采用可恢复的沉淀流程：

```text
session 观察 → 候选审查 → 对照 personal 既有记忆
            → 新建 / 补充 / 修订 / 保留为暂时信息 / 放弃
```

审查必须回答：未来哪类任务会用到；是否超出本轮临时状态；事实还是推断；适用对象/版本/条件是什么；来源是否足够；已有知识是否能承载这次增量。不能以出现次数、搜索次数或记忆层级作为自动升级阈值。

晋升生成独立、完整的长期知识版本，保留提炼依据和必要的可长期核查证据。不要整段复制日志，也不要只写几个关键词。session 过期后，personal 不能只剩一个指向已删除会话正文的证据链接；需保留必要的依据摘录或持久源码引用，并明确尚未核查的部分。

里程碑和关闭前可触发审查；来不及则留下真正会被消费的审查工作。审查完成与投递 checkpoint 完成是两件事。延期不能最终被一个只审已有长期记忆的空整理计划替代。

## Team 的用户发起写入

共享是一项显式发布行为。用户说“把这次 sample-project 审查结论总结到团队记忆”，已授权 agent 完成该范围的总结和发布，不需要每条记忆反复询问。普通任务、阅读团队资料、agent 判断“同事可能有用”均不能自行触发团队写入。

建议以真实用户事件为依据，由宿主创建可校验的 team 写入授权，绑定团队、请求、允许的操作/对象范围、有效期及幂等身份。LLM 可引用授权，但不能通过自行填一个 userInitiated=true 获得授权。该要求应在服务提交入口校验，不能仅靠提示词。

用户发起一次“整理团队知识”可以覆盖一批补关联、去重和画像修订，提交仍沿用同一次工作身份。新增共享、扩大范围、脱离该请求的后台语义改写需要新的用户请求；索引重建等不改变知识语义的维护可正常自动执行。用户也可以主动配置一项明确范围的周期任务，但不能从一次性请求推断出永久授权。

团队版本与个人版本独立演进。Personal 更新不能自动改写已发布的 team 内容；团队有更新时可告知 personal 记录待复核，不能把两份记录共享一个可随意修改的正文指针。

跨域可保留 publishedFrom/derivedFrom 等带版本的来源关系，用于追溯和失效提示，不作为涟漪边。底层允许复用不可变文本存储，但各域拥有独立记录、修订和生命周期。用户此前要求的“同一记忆在多个维度存在”仍保留在单域内；跨域发布具有额外的版本边界。

## 独立的协作状态模块

待办、认领、阻塞、交接和完成凭据应采用结构化 TaskBoard，不能用自然语言记忆的相似度、importance 或整理合并来决定当前状态。

建议 MindPond 提供可选的持久协作存储接口，宿主继续负责调度 agent、代码工作树及实际副作用。已有宿主任务系统时直接适配同一事实来源，不另外维护一份会漂移的 todolist。

最小对象：

```text
WorkContext: id, goal, participants, sessionRefs, status
Task: id, workContextId, parentId?, title, acceptanceCriteria,
      status, dependencies, assignee?, revision,
      claimToken?, attempt?, leaseUntil?, resultRefs, blockers
TaskEvent: taskId, actor, eventId, expectedRevision, transition, reason, timestamp
```

最小操作为创建/拆分任务、查看依赖、原子认领、续租、报告阻塞、提交结果、验收完成、交接与取消。用版本检查防止并发覆盖，用租约和领取代次拒绝旧 agent 的晚到结果。工作者提交结果不必等于验收完成；失联可恢复但不能把有外部副作用的任务直接认定可重复执行，是否重跑由宿主结合回执决定。

Task 的描述、评论、附件都是协作内容，不能因“它位于任务看板”就允许 agent 通过共享看板向团队发布任意个人资料。共享给哪些参与者由用户启动的协作工作范围决定；保存成长期 team 知识仍走上面的发布规则。

建议协同处理同一会话的 agents 共享逻辑 sessionId，各有自己的 agentId/runId。来自独立会话的协作 agent 保留各自 session，只通过 WorkContext 共享明确的任务状态和交接材料，不能借工作看板读取其他完整 session。

任务结束后可有限保留可恢复/审计状态，但默认不进长期知识搜索。仅将得到的可复用经验、设计决策和已验证结论沉淀到 personal；存 team 仍须用户发起。与 MindPond 内部的 host_work/organization job 分开命名和存储，避免把“整理记忆的工作”误作“用户项目的待办”。

## 一个完整例子

用户让三个 agents 审查 sample-project。任务板分配入口流程、存储和教学反馈三个任务，记录依赖、认领和验收；当前 session 保存具体调查过程、暂时猜测和中间结论。

Agent 发现一个已验证的持久化约束，将包含源码版本、成立条件和未知范围的知识保存到 personal 的项目空间。整理可补上与既有重试经验的关联，也可生成个人流程画像。下次换 agent、换 session 仍能读这些长期知识，旧会话的日志和任务状态不混入召回。

用户随后要求“把确认后的架构与风险总结到团队”。Agent 在该请求下形成自包含的团队记录，保留必要来源和独立版本，不把所有调查日志一起发布。之后个人又验证出新情况，只更新 personal 并提示已发布结论可能需要复核，不能默默改 team。

## 已实现边界与后续顺序

当前实现为每个节点、整理 job 和 host work 记录 `domainRef`，并将它与 `spaceId/memoryType` 分离。旧节点迁移为 personal/default；旧的 sessionId 节点迁移至对应 session domain，不会被自动发布到 team。搜索、列表、向量候选、图展开和整理候选都先检查 domain；默认读取 personal/default，加上调用方明确给出的当前 session。关闭的 session 从正常读取和任务看板中消失，显式 purge 才删除它的节点、索引和关联。

team 写入使用 `MEMORY_TEAM_AUTH_SECRET` 验证宿主签名的短期 grant，绑定 team、操作和过期时间。保存、编辑、删除、membership、association、association review/delete、team organization commit 和 team WorkContext 创建都会校验。签发 grant 是宿主在真实用户事件发生时的责任，签名密钥绝不能进入 LLM 上下文、MCP 工具参数或前端；它不是完整的团队成员权限系统。

TaskBoard 已提供持久 WorkContext、Task 和审计事件，含依赖、原子认领、租约、乐观 revision、提交和验收。任务状态不自动写成记忆。宿主仍负责实际调度、agent 身份和外部副作用回执；部署时须验证任务冲突、召回范围和人工验收流程；宿主调度与完整团队成员管理不由核心替代。

## 必须验证的行为

- 新 session 无法通过省略过滤、传旧 memoryId、画像支持展开或图路径读出旧 session 记忆；同用户 personal 和已接入 team 仍可正常读取。
- 当前 session 因压缩/重启恢复仍保有上下文；过期清理后个人知识的必要依据仍完整，延期工作不会永久阻止清理。
- 清晰长期事实可直接存 personal，暂时猜测不会仅因被反复引用而升级；重复记忆更新既有知识而非无限新增。
- 没有真实用户请求时，team 的保存、修改、补关联和画像合成都不能提交；授权范围内的一次批量总结无需反复确认，故障重试不重复发布。
- 编辑 personal 不改 team 已发布版本；来源变化能提示影响，不能静默跨域重写。
- 20 个 agents 并发认领任务，只有一个当前有效领取者；过期领取、旧修订和重复完成可正确处理；任务完成不会直接制造一条长期记忆。
- 相同查询测量各 domain 的有效材料、无用过程信息占比和总 token；个人长期知识质量由独立评审的来源/条件保留情况判断，不能以节点减少或自动存储数量作为成功指标。
