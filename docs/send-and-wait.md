# 发消息并等待反馈

## 为什么需要它

以前角色发完消息，调用立刻返回。后续是否主动调用 `office_wait`、等待多久，都要依赖 LLM 再作决定。现在可以把「发送」和「等反馈」合成一次 MCP 调用，减少发送后直接结束、需要人类反复提醒的情况。

## Agent 怎么调用

```json
{
  "action": "send",
  "recipient": "目标角色编号",
  "body": "请检查这份方案，完成后回复这条消息或提交处理结果。",
  "key": "review-plan-1",
  "waitForReply": true,
  "waitSeconds": 10
}
```

- 工具为 `office_message`，`waitSeconds` 单位是**秒**，可填 1–300；选择等待但不填时默认 300 秒。
- 不选择 `waitForReply`，或设为 `false`，按普通发送立即返回。不能只填时长却不选择等待，也不能在读取／领取／结束消息时填写等待参数；参数错误会在发送前拒绝。
- 发送失败立即返回错误，不进入等待。发送成功先提交、返回消息编号的回执持久化，再等待；等待期间不持有数据库事务或连接协调锁。
- 等待期间，**任何发给当前角色的新消息**都会立即结束等待，并直接返回完整正文、发送者、消息编号、元信息和附件引用。等待开始时已有的待处理消息也会直接交付，优先按收件顺序处理。
- 接收和领取在同一事务中完成，新消息自动变为「处理中」，无需另调 `get` 或 `take`。处理完再调用 `office_message finish`，使用返回的 `receivedMessageId`；顶层 `messageId / sentMessageId` 是原来发出的消息编号，不能混淆。
- `replyWait.isReplyToSentMessage` 表示收到的消息是否引用了原发送消息。其它新消息也会唤起角色，但不表示原任务完成。目标角色可用 `replyTo`／`replyToSeq` 回复，或领取后 `finish` 产生关联反馈。仅领取原消息和会议邀请不算新收件。人类停止／暂停、已进入的会议室焦点、取消、权限变动和连接关闭仍可中断等待。
- 返回 `replyWait`，包含 `status`、`requestedSeconds`、`minimumSeconds`、`effectiveSeconds`、`minimumApplied` 和计时／下一步。`matched` 表示交付了完整新消息，`replyWait.message.complete=true`。新消息可以是其它工作，不表示原任务已验收。大消息也直接返回完整内容，不用额外拼接正文页面。

## 人类怎样设定最短等待

登录前端，进入 **连接设置 → 发信后等待反馈**，填写最短等待窗口（秒）并保存。

例如填 `300`（5 分钟）：角色请求等 10 秒，实际窗口为 `max(10,300)=300` 秒。期间一旦收到发给该角色的新消息就立即返回，**不是收到了消息还要空等满 5 分钟**。

- `0` 表示不设下限；本轮沿用服务的五分钟单次上限，因此可设 0–300 秒。生成的宿主配置保留至少 360 秒调用期限。
- 配置对所有共用此数据库的 MCP 进程生效，只有人类管理者可以修改。采用版本核对，冲突不覆盖别人的更改，前端轮询不覆盖未保存草稿。
- 新值用于之后开始的发送等待；不追溯延长已在途的窗口。不强迫所有消息等待，也不改变独立 `office_wait` 的毫秒参数语义。
- 如果宿主自己提前取消请求、客户端期限过短或连接中断，服务器不能让客户端继续保持调用；这类情况应明确区分中断与正常超时。

## 超时、重试和身份

发送成功后超时，消息仍然已发送。结果保留 `sent=true`、`messageId` 和 `replyWait.status=timeout`；不要换一个发送键再发一遍。

在用户授权的等待范围内，使用**同一消息内容、同一 key**再次调用，可以继续等待而不重复投递。等待选项不参与消息内容的幂等哈希，可调整等待秒数，或改为普通发送查回原回执。幂等回执仍属于当前角色绑定；人类切换／解绑后须先恢复身份，不能把另一身份的键当作已有投递证明。

等待中发生错误会明确指出消息已发送，并保留编号、等待配置、错误原因与下一步；发送错误不会假装成功。调用被客户端取消时响应可能无法送达，但原发送回执不会被撤销。同一绑定重连后仍可按原键恢复。

如果新消息已被本次发送等待领取、但响应丢失，按同一原发送 key 重试会恢复这条「处理中」消息，而不是再取走下一条；完成归档后不会自动重复投递。不同发送等待并发领取时，以原子事务避免拿走同一条新工作。普通独立 `office_wait` 仍只观察，不领取。

保持现有角色、办公室、会议室与附件权限。此功能不启动／恢复宿主，不向终端注入文字，不引入新软件或模型依赖。
