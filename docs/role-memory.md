# 人类、角色与独立记忆连接

一个 MindPond server 当前按服务一个人类用户设计。

| 身份 | 可以读取 | 可以保存、整理 |
| --- | --- | --- |
| user（人类） | 所有记忆，包括角色知识 | 人类知识；在管理页面分配、编辑角色知识 |
| agent（Office 角色） | 自己保存或人类明确添加的知识 | 自己的知识；不能选择其他身份 |

记忆搜索默认跨工作空间。项目、分类和旧存储域是内部组织信息，不是新连接的身份选择方式。已有记忆保留在原数据库，由人类视图检索；不会自动给所有角色开放。人类专属 token 尚未实现，本机人类连接与管理页面应保留给用户自己的可信宿主。

## 分开配置两个 MCP

- Office：中心地址的 `/mcp`，提供角色、消息、办公室操作。注册宿主的 Office 连接不提供 `memory_*` 读写工具。
- Memory：同一中心地址的 `/memory/mcp`，只提供记忆工具。使用同一宿主认证和可信聊天 ID 时，服务端自动查到该聊天的角色。
- 本机人类 Memory：`mindpond-mcp` 的默认 stdio 入口提供独立记忆工具，身份为 user；不需要传 workspace、domain、sessionId 或 roleId。

角色连接没有绑定时，Memory 返回需要激活或批准角色，不能自动变成人类身份。模型传入任意角色 ID 不能切换权限。读取未知 ID、其他人的记忆都不会返回正文。

### OpenCode：同一配置可用于不同聊天

网页和 `mindpond-connect office-prepare` 生成的 OpenCode 配置包含两个独立 MCP，以及 `.opencode/plugins/mindpond-session-*.js` 会话插件。安装后重启 OpenCode。

1. 用户将连接凭据保存在宿主设置或环境变量，不发给模型。
2. 插件在调用前从 OpenCode 的真实 `sessionID` 获取聊天身份，从宿主配置取得该 MCP 的认证凭据。
3. 插件对聊天 ID、工具名、完整参数摘要和时间签名。MindPond 验证后再解析身份，参数被改动或签名过期会拒绝。
4. 新聊天单独申请、批准角色；重新打开同一聊天恢复其原绑定。

支持 `ai.opencode/sessionID` 元数据的新版宿主也可直接传递原生 ID。真实聊天 ID 优先于安装配置中的固定标签，解决不同聊天共用固定标签而串角色的问题。旧版由签名插件提供同样的持久聊天关联；单纯的 MCP transport session ID 不能代表聊天。

### 没有可靠聊天 ID 的客户端

可以在前端批准“激活已有角色”请求。激活会把所选角色绑定到新聊天，并撤销该角色旧绑定；消息及独立记忆保留。

也可以在记忆页选择角色，下载角色专用连接配置。角色凭据是宿主保存的权限凭据，连接重建仍指向同一角色；可用于独立 Office 和 Memory 连接。重新生成凭据会撤销旧凭据，停用或删除角色后也不能再使用。

角色专用配置放在该角色使用的宿主环境。宿主同时提供聊天 ID 时，服务端还会校验该聊天确实绑定同一角色；把一个角色配置错误地用于另一个已绑定聊天会被拒绝。没有聊天标识、没有角色凭据的共享连接无法可靠区分多个聊天，此时须使用独立连接并由用户确认，不能猜测“最近使用的角色”。

## 连接何时回收

- 临时 HTTP MCP 连接默认空闲30分钟回收；正在执行的调用不会按空闲连接清理。
- 角色绑定存数据库，连接回收或服务重启不删除角色、消息和知识。
- 可信聊天 ID 或角色凭据可以重建连接并恢复身份，无须反复激活。
- 未确认且24小时无活动的激活请求过期，并有数量上限。
- 角色凭据没有短期自动过期；用户可以轮换、停用或删除角色来撤权。
- 共享聊天连接使用普通可恢复等待；实验 MCP Tasks 仅在固定角色凭据连接中提供，防止任务句柄落入共享安装标签的身份。

## 将知识添加给角色

例如让“资料审阅员”只关心环境排错和审阅经验：

1. 人类打开记忆搜索，输入“环境排错”。默认搜索全部记忆，也可选一个角色查看其知识。
2. 阅读 Markdown 正文与来源，勾选需要的知识。
3. 点击“添加给角色”，选择“资料审阅员”并确认。
4. 服务端为该角色创建独立副本，保存原记忆 ID、版本和内容哈希。同一来源重复添加会返回已有副本，保留角色自己的修改。

副本后续可独立整理。原文更新不会自动覆盖副本，原文删除也不删除副本；来源引用使人类可以核对当时复制的版本。不会复制原文指向其他私人知识的关联边，避免通过图遍历扩大角色权限。

## 验证范围

`npm run verify:role-memory` 使用真实隔离 SQLite、两个 HTTP MCP 服务目录和生成的宿主插件验证身份、权限、复制、重连与撤权。默认回归不调用模型。

`MINDPOND_TEST_OPENCODE_BIN=/path/to/opencode npm run verify:opencode-role-session` 使用已安装 OpenCode 的真实插件加载、宿主配置读取和两个 `noReply` 会话事件，再通过真实 MCP 验证角色身份。它不执行模型推理；工具执行钩子的签名和参数绑定由独立 HTTP MCP 回归覆盖。它不证明模型理解或记忆准确率一定提高。
