# 办公室守则

办公室守则由人类设置，服务在角色的协作 MCP 返回中适时提醒。无需修改 Codex、OpenCode 或其他宿主；提醒只增加一段上下文，不能保证模型遵守，也不会替模型调用 Memory。

## 在页面设置

1. 打开一间办公室，点右上角 **办公室设置 → 办公室守则**。
2. 编辑默认内容，或点 **添加守则**。每条守则有名字、内容和自己的提醒频率。
3. 点 **保存守则**。下次符合条件的通信返回时生效；后台刷新不会覆盖尚未保存的草稿。

例如，可以保留默认的记忆守则为「均衡」，另加一条「交接先写清材料版本」并设为「轻量」。需要加强某项提醒时，把该条改成「每次提醒」。

最多8条守则，正文合计最多2048个 UTF-8 字节；页面实时显示用量。文字越短，重复提醒的 token 消耗越低。「关闭」保留内容但不再提醒；删掉全部守则则完全关闭。**恢复默认守则**只修改编辑草稿，仍须保存才生效。

多人或多窗口同时编辑时，旧版本保存会被拒绝，草稿保留；按 **重新载入** 核对当前版本后再编辑。管理凭据不会交给角色，角色不能通过消息、容器或 MCP 参数修改这些守则。编辑守则不会改动工位、消息状态或任务领取权。

## 默认的记忆守则

> 接任务先用独立 Memory MCP 的 memory_brief 查经验；阶段完成或交接前，保存或更新值得复用的已验证结论、步骤与坑点，注明条件和依据，先查重。个人经验存角色，共同知识指定 officeId。勿存流水账或密钥；身份不符先查 memory_identity，勿写入人类记忆。

现有及新办公室默认都只有这一条，频率为「均衡」。不需要写入初始化数据，已有办公室的角色、记忆和消息保持原样。

## 频率怎样计算

| 档位 | 提醒方式 |
| --- | --- |
| 关闭 | 不注入 |
| 每次提醒 | 每次符合条件的通信返回都提醒 |
| 均衡（默认） | 首次提醒，此后每4次成功通信返回提醒 |
| 轻量 | 首次提醒，此后每8次成功通信返回提醒 |
| 每16次 | 首次提醒，此后每16次成功通信返回提醒 |
| 每32次 | 首次提醒，此后每32次成功通信返回提醒 |
| 每64次 | 首次提醒，此后每64次成功通信返回提醒 |
| 每128次 | 首次提醒，此后每128次成功通信返回提醒 |

按 **角色 × 办公室** 分别计数，每条守则按自己的档位计算。新绑定聊天、守则保存为新版本后，下一次会重新提醒。`role_sync` 可在首次或绑定/版本变化后带回守则，重复同步不消耗日常通信计数。

- 普通消息发送、查看、领取和完成反馈，以及广播，都是提醒机会。
- 收件箱确实返回消息时计一次；一页多条也只计一次。同一条消息再次查看或成功幂等重试，也算一次返回机会，原消息的幂等性不变。
- 会议室创建、加入、发言、处理确认、离开，以及获取到内容或更新的等待结果，也可提醒。
- 空收件箱、没有内容的会议读取、等待超时、失败操作和 Memory 查询不计数。

计数保存在 SQLite，重启、不同传输连接及并发调用不会各自重算。多办公室同时有提醒时，总正文按完整规则预算返回，未放下的办公室留到后续机会，避免截断规则或长期挤掉某个办公室。这里没有额外模型调用或外部服务。

## 范围与可信边界

提醒在 `officeGuidance` 中单独呈现，不拼进协作者消息正文，不会转发发送者的私人办公室守则。带办公室的通信使用该办公室的守则，讨论使用其所属办公室的守则；直接通信使用角色当前主要办公室。只有当前工位、宿主与项目授权仍允许访问的办公室才会提供守则。读取离开办公室前的历史消息，不会恢复该办公室的守则或知识权限。

守则不扩大记忆或文件权限，不改变临时讨论室的通信限制，不构成额外执行授权。Office 与 Memory 继续分开接入。使用模型可见的记忆引用和提示，仍由角色判断何时检索、如何整理，以及哪些知识值得保留。

如果提醒暂时失败，返回 `officeGuidanceUnavailable` 并说明只影响提醒；已成功的消息不会因此变成失败，也不应为了重新获得提示而重发消息。大型通信响应仍遵循已有完整分页规则。

## 升级

新增 `office_rule_policies` 和 `office_rule_delivery` 两张表，启动时在短事务中幂等创建，无新依赖或模型文件。所有共用数据库的程序升级到同一版本。刷新页面、重新连接 MCP 后即可使用；已归档办公室不再注入或修改守则，删除办公室或角色时相应计数自动清理。
