# 通用 MCP 的生产优化

实现原则：标准 MCP 独立可用；原生聊天识别为可选增强；身份故障不扩大权限；流程允许跳过非必要步骤、部分完成和人工恢复；记忆质量由 LLM 与人类维护。保持 Office / Memory 独立、角色六邻居图能力和现有部署边界。

| 顺序 | 交付与验收 |
| --- | --- |
| P0 身份与接入 | 通用连接身份、可选逐聊天身份；一份配置包含双 MCP；重连、不同凭据隔离、撤权与身份故障回归 |
| P0 工作恢复 | 人类核对处理中消息、取消并重新安排；不自动宣称完成或重试外部动作；恢复保留来源与幂等回执 |
| P0 离线发布 | 程序/前端版本、平台与依赖清单、校验和；断网运行验收及备份恢复；正式版本策略，不上传私人数据 |
| P1 运维与容量 | 简洁运行页、有限指标、磁盘/数据库/WAL/队列/备份状态；合成容量基线与可重复命令；优化无变化同步 |
| P1 记忆维护 | 保留现有搜索、Markdown、归属、副本、锁、来源、历史与撤销；不添加强制总结、自动质量判定或破坏式清理 |
| P1 效果验证 | 现有隔离对照驱动保持可用；样本与消耗完整记录；无宿主/无推理授权则明确未运行，不把工程回归当效果收益 |
| P2 易用性 | 连接范围清楚、待处理入口、运行状态页、命名与空状态、窄窗口与长文；保留草稿和阅读位置 |
| P2 讨论与脚本 | 目标、结束条件和保存结论入口；源码版本、依赖/用法、哈希；不自动执行或额外授予权限 |
| P2 工程契约 | 无依赖膨胀；故障、并发、跨 MCP 身份、异步页面及真实浏览器验收；删除替代的失效路径 |

通用连接模式共享配置即共享身份，不声称能识别宿主未提供的聊天。逐聊天模式缺少可信标识时明确拒绝 Memory，保留人工处理路径；不猜测、不按最近连接选择角色。生产域名、实际离线平台、宿主与真实模型效果需各自验收。

## 本轮交付与验证边界

通用身份覆盖双 HTTP MCP 与 stdio 桥接；已观察的连接可断开和迁移角色。运行维护集中到独立页面，删除重复弹窗实现；完整性检查带时间并缓存，容量草稿不被自动刷新覆盖。接入指南替换过时截图，新增截图仅含合成角色/连接，没有访问凭据或运行数据。

默认回归、实际 Codex/OpenCode 的无推理身份验收、真实离线目录生成与合成容量基线分别执行。真实模型效果沿用现有对照工具，不在用户日常流程中强制执行，也不宣称已有质量提升。目标生产机的网络、模型、数据迁移与恢复仍按生产验收文档核对，不能由本机合成测试代替。
