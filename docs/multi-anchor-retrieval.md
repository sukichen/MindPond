# 多锚点召回：接口、边界和验收

实现日期：2026-09-16；2026-09-20 完成与多维桥接的集成复验。锚点是完整记忆的检索入口，不是新的记忆节点，不自动建边，也不代表该记忆适用于当前任务。MindPond 不需要宿主的 LLM key。

## 存储与修改

SDK `save`、HTTP `/api/memory/save`、MCP `memory_save` 和自动提炼提交均接受 `anchors`。旧客户端可以省略。建议 2–4 个有区别的入口，整条记忆所有空间合计最多 6 个。

```json
{
  "content": "项目 P 本地调试服务修改端口后，必须同步修改代理目标；远程调试经代理进行，不直接开放公网监听。",
  "memberships": [{"spaceId":"project:P","memoryType":"configuration"}],
  "anchors": [{
    "text":"项目 P 改端口后远程调试失败",
    "basis":"修改端口后，必须同步修改代理目标",
    "spaceId":"project:P",
    "memoryType":"configuration"
  }],
  "idempotencyKey":"host/run/observation-1"
}
```

每个入口的 `text` 为 1–240 字符，`basis` 为正文中的精确摘录（1–1000 字符）。服务验证数量、重复项、依据摘录及空间归属；宿主负责语义和适用性判断，摘录存在并不能证明入口的语义一定正确。空间名和类型必须与此记忆的活跃成员一致。

`memory_update`/SDK `update` 接受 `anchors`，表示替换整条记忆的入口，必须提供读到的 `expectedUpdatedAt`。空数组表示清除。正文发生变化时，数据库触发器将全部旧入口标记 `needs_review` 并停止召回；只有显式复核并提交的新入口恢复活跃。标签变化不使正文依据失效。删除记忆、清除会话时锚点跟随级联删除。

工作台记忆详情可编辑锚点 JSON，并需勾选已复核后提交；搜索结果展示命中入口。字段只含检索表达、来源摘录和范围，不存隐藏推理。

## 召回及涟漪

正文主向量、正文中文向量、正文文本检索继续保留。锚点独立生成向量并提供双字片段文本检索；模型不可用时文本入口仍工作。各模型的向量只在相同模型通道内比较。入口列表按数据库版本缓存，其他进程保存、修改、删除后会刷新；缺失向量有有界后台补建。

不同通道使用排名融合，输出的是 0–1 的相对入口强度，**不是概率**。不再混加不同模型的原始余弦，也移除了“含问号即降权”“短正文优先”以及单通道提前返回的特殊分支。每个通道先按记忆聚合排名；多个锚点不累加，每个锚点模型通道共享一次锚点支持票。第一名保留交叉支持的加分空间，避免各路第一名都直接封顶、由随机 ID 决定顺序。

域和会话可见性在锚点评分之前检查；空间/类型也在入口阶段检查。锚点只激活所绑定成员，不借共享正文进入其他空间。每条路径仍为入口强度乘该路径的边权，多个直接命中并行传播。`matchedAnchors` 解释路径的起点；沿途依据在 `associationPath` 中，两者不可混为一谈。

`useAnchors:false` 可用于 HTTP/MCP/GraphMemory 搜索对照，SDK `search` 同样支持。正文召回仍可独立激活它的合格空间成员。现有 `minScore` 的数值含义随排序修正改变，应通过固定样本校准，不能继续当作余弦阈值解释。

## 整理与宿主协作

存储规则升级为 `memory-save.v2.5`。宿主应根据对象/别名、未来问题、工作场景、约束或故障征兆生成不同入口，不凑满六个同义词。场景如果只在当前对话中出现，应先把必要条件写入正文。

组织计划增加 `reanchor`：

```json
{"operations":[{
  "kind":"reanchor",
  "membershipIds":["从单条或多条 claim 获得的成员 ID"],
  "anchors":[{"text":"具体未来问题","basis":"当前正文原文摘录","spaceId":"当前任务空间","memoryType":"当前任务类型"}],
  "reason":"复核完整正文后，解释为何保留这些入口"
}]}
```

显式 `membershipIds` 可只领取一个成员用于复核；自动批次仍默认至少两个。`reanchor` 只替换当前空间/类型的入口，并保留其他空间；全局仍不能超过六个。合并和综合操作可为新正文提交锚点。未提交时不会擅自把旧锚点复制到新正文。旧记忆不会自动批量补写：宿主使用已有整理领取、完整读取、验证、提交协议逐批处理。

现有 recall 回执记录命中的 anchor ID，宿主仍按记忆报告 used/rejected/unassessed。仅仅被召回或注入提示词不是采用。反馈不会自动加强边或删除低频入口。场景适用性复核由宿主执行；本次未引入额外的在线 LLM 重排调用或训练好的专用重排模型。

## 验证命令

```bash
npm run verify:anchors
npm run check
npm run eval:anchors
```

契约测试使用临时 SQLite 和确定性向量，覆盖：数量与依据校验、幂等冲突、不同措辞的向量命中、只进入对应空间、两跳乘权、六入口不重复计分、正文失效与跨实例刷新、复核恢复、向量故障降级、中文通道、session 隔离、反馈和级联删除。HTTP/MCP 真实进程测试另覆盖 save/get/search/update/reanchor。
