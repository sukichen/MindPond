# 角色合并与拆分

由人类管理者在「角色与申请 → 点击角色 → 合并 / 拆分」操作。无需模型、额外依赖或宿主适配。系统不根据相似度自动决定角色定位，也不自动合并相似记忆。

## 合并：保留一个主角色

例如「接口审阅员」和「后端审阅员」的定位逐渐重合：打开接口审阅员，选择“合并到主角色”，选后端审阅员作为主角色，核对调整后的名字、定位与职责，点击“预览影响”。

- 来源角色全部私有记忆迁入主角色，保留原记忆编号、向量、内部关联及权重；内容不改写、不自动去重。
- 私有脚本与附件迁移归属，脚本锁、附件原始字节、SHA-256、已有第三方接收者、到期时间保持不变。相同文件名仍以不同编号区分；不会自动扩大附件的共享范围。来源角色作为其它附件指定接收者的权限也转交主角色；来源角色拥有的办公室附件也由主角色管理，但下载仍要求当前办公室授权。
- 主角色获得来源角色的办公室资格。两个角色都在同一办公室时，保留主角色工位与分工，来源角色工位停用；其它办公室工位转交给主角色。共享记忆及办公室脚本保持原位。
- 工作任务全部迁移。任务编号冲突时为来源任务生成新编号，不覆盖主角色任务。摘要范围冲突时，可选保留主角色或来源角色摘要；两份摘要都保留在主角色的工作历史中。
- 已处理消息转由主角色查看及接续，保留消息当时的姓名，并另外保留原发送者/接收者编号记录。两个被合并角色之间的历史通信可能成为同一角色的历史记录，不能给自己发送新回复。
- 来源角色退出角色和记忆归属目录，保留历史归属记录，不能重新启用。发送给该角色会得到合并目标提示，不会悄悄改投。来源角色尚未接受的会议邀请失效，需要重新邀请主角色。
- 人类设定的跨账户联系人权限与暂停/停止请求随合并迁移。私有经验仍只归主角色，人类仍可统一管理全部记忆。

## 拆分：选择迁出内容，建立新角色

例如将「研发助理」中的部署经验拆为「部署助理」：选择“拆出新角色”，填写新角色定位，按类别搜索并勾选记忆、脚本、任务、摘要、附件或办公室，预览后确认。

- 选中内容**移动**到新角色，未选内容留在原角色。每个类别可跨搜索/分页保留选择，一次最多选择 1000 项，摘要最多 50 个范围。
- 选择办公室为新角色增加成员资格，原角色仍保留资格。选择办公室进度时，须同时选择对应办公室。加入不绕过项目、宿主或凭据的授权检查。
- 不复制整份私信记录。引用私信的进度应先整理成可迁移记忆，再拆分；进度与其引用的角色记忆须一起迁移或一起保留。
- 内部记忆关联保持；跨越两角色边界的关联及引用边会断开，数量列在预览中。同时涉及拆分两侧记忆的改进建议转交人类处理，避免通过建议队列泄露另一侧内容。综合记忆与依据、记忆及替代版本必须整体选择，避免形成不完整的证据链。
- 角色独有附件的接收者不自动增加：原角色如果仅是附件所有者，迁走后不再拥有该附件；已有指定接收者仍按原范围授权。办公室附件留在办公室，不列入拆分选择。

## 预览、执行与重新连接

1. 请先处理并归档双方尚未完成的消息，总结退出会议室，发送或丢弃会后待发消息；完成或取消负责/审核的办公室工作项，结束记忆整理，完成或删除待上传附件。未完成事项会显示为阻塞原因，执行不会丢弃它们。
2. 检查预览中的迁移数量、办公室数、断边数量和摘要冲突。脚本、任务、附件和成员数量沿用现有限制，超额时先整理。
3. 预览有效期 15 分钟。角色、记忆、工作状态或权限变化后必须重新预览；执行在一个 SQLite 事务中完成，失败全部回滚。
4. 合并会断开两个角色的聊天连接；拆分会断开原角色，新角色初始未连接。角色专用 Memory 凭据撤销，在途写入按绑定版本拒绝。原角色的工作进度写入回执失效；迁走记忆的保存回执也不能在原归属重放。重新读取身份及当前进度后，新写入使用新 key。**断开后的聊天按既有规则恢复为人类身份**，请重新绑定角色后再继续角色工作。
5. 在角色详情中“连接到聊天”，绑定相应 Codex、OpenCode 或其他 MCP 聊天；通过独立 Memory MCP 的 `memory_identity` 确认身份，再 `memory_resume` 恢复任务。办公室访问在重新绑定后按当前宿主权限重新计算。
6. 网络响应丢失时可以直接重试“确认并执行”；相同预览只执行一次。预览草稿过期后可清理，已执行记录保留以便审计及避免重复执行。

这不是数据库回滚功能，也不自动还原已拆开的关联。生产操作前按现有部署流程备份数据库与附件目录。执行过归属调整后若需回退，应恢复匹配的数据快照，不能只降级代码。升级本功能仅创建三张管理表，不自动迁移已有角色；使用同一数据库的所有进程须一起更新并重启，随后刷新网页。
